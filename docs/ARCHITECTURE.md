# Архитектура и модель

React обращается к FastAPI по HTTPS (локально — loopback HTTP). Сайт не содержит данных архива или секретов и может размещаться на GitHub Pages. Для удобства локальный FastAPI также отдаёт готовый frontend/dist. HashRouter совместим со статической публикацией.

Сессии — случайные непрозрачные bearer-токены; в SQLite только SHA-256 токена. В браузере токен хранится только в React state и теряется при перезагрузке. Коды — Argon2id. Роли проверяются на каждом API endpoint. CORS ограничен одним origin. Оригиналы не подключены как StaticFiles. Подписанные ссылки привязаны к сохранённой записи разрешения и HMAC-SHA256: ID, страница, операция, координаты, время создания и истечения. Любое изменение нарушает подпись; дополнительно проверяются отзыв, права дела, время и атомарный лимит обращений. Ответы no-store/no-referrer. Ключ лежит в защищённой `data_dir/signing.key` (в переносном режиме — `.drevo` внешнего диска).

## Каталог

Case хранит архив, фонд, опись, номер дела и предварительные реквизиты. Иерархия архив/фонд/опись выводится из индексированных полей Case; metadata_json хранит годы, исторические топонимы, церкви, источник копий. Section — отдельное поле страницы, а не номер. Page хранит номер JPG, страницу книги и архивный лист раздельно, оригинальное имя, разрешение, формат, SHA-256, путь и ZIP member. Пути не возвращаются обычному просмотрщику. ID детерминирован по делу и исходной ссылке. Совпадение SHA помечает копию, но не удаляет документ.

## Исследования

Entity использует единое версионируемое хранилище и строгие типы kind: Person, PersonMention, HistoricalRecord, Claim, Evidence, Transcription, Relationship, ResearchTask, Finding, Annotation, Hypothesis. Эти типы не взаимозаменяются и не объединяются автоматически. Pydantic/JSON Schema валидирует поля, ссылки и UUID. Источники содержат page_id и crop в координатах оригинала. Неуверенное прочтение требует вырезки. Review хранится как неизменяемое событие AuditEvent с автором, комментарием, before/after и временем. Отклонённые записи сохраняются, физическое удаление и массовое объединение не предоставлены.

Предложения ChatGPT имеют proposed; сомнения сохраняются в uncertain. Ручные записи с сомнениями могут иметь needs_review. Система различает проверку прочтения (human_reviewed) и подтверждение факта (confirmed). Для родства нужны подтверждённые Evidence и явное существенное подтверждение. AI не обновляет подтверждённые факты: propose_correction создаёт отдельное предложение; конфликт версий не перезаписывает оригинал. Подтверждение предложения исправления человеком применяет replacement_data к исходной записи только при совпадении expected_version, с отдельной историей обеих записей и явным согласием на изменение подтверждённого факта. Для независимой новой версии пользователь также может сохранить отдельное предложение.

Календарь хранится как julian/gregorian/unknown; оригинальная строка даты всегда отдельно. При unknown современный эквивалент запрещён. Неполные, примерные и противоречивые даты — отдельные элементы массива. Система не выводит календарь из года или региона.

ResearchTask хранит цель, исходные факты и предположения, список дел, просмотренные/полностью изученные страницы, кандидатов, отвергнутых кандидатов и следующий шаг. Просмотр вырезки не помечает всю страницу изученной. Такой переход выполняется отдельным действием пользователя.

SQLite FTS5 содержит индекс исторических данных; поиск похожих возвращает кандидатов. Нормализация включает регистр, ё/е и исторические ѣ/і, не изменяет оригинал. SQLAlchemy и Alembic управляют основной схемой, SQLite WAL используется на локальном диске. Бинарные изображения не сохраняются в SQLite.

## GitHub-проекция

Отдельный worker читает только requests/*/*.json и inbox/*/*.json, проверяет private репозиторий, разрешённые операции, размер и UUID. Транспорт — GitHub Contents REST API, каждое обновление использует текущий SHA; 409 требует повторного чтения. Обработанное сообщение и квитанция хранятся в SQLite, поэтому сбой после DB commit до GitHub PUT не дублирует результат. Cursor сохраняет SHA обработанного blob и последний commit дерева. Исследовательский контекст экспортируется небольшими JSON-шардами, manifest — точка входа.

living=true исключает запись и связанные сущности из проекции, если DREVO_EXPORT_LIVING=false. Автоматическое распознавание живых людей в свободном тексте не выполняется: автор обязан правильно классифицировать чувствительные записи. Репозиторий всё равно должен быть приватным. Изменение настроек приватности не удаляет ранее сделанные Git-коммиты; перед первой синхронизацией проверьте классификацию данных.

## Ограничения текущей версии

Просмотрщик загружает защищённое JPEG-превью до 4096 px и пересчитывает выделение в координаты оригинала; оригинал и вырезки доступны отдельно. Это не IIIF tile server: для очень больших TIFF потребуется отдельная пирамида/pyvips. ZIP, TIFF и крупные crop ограничены по памяти и размеру. Правила нормализации редактируются в настройках с перестроением FTS5, исходный текст при этом сохраняется. Все URL с токенами — временные секреты и должны храниться только в приватном репозитории. Полная работоспособность обычного ChatGPT зависит от реально доступных операций GitHub и веб-инструмента; интерфейс явно оставляет unverified.
