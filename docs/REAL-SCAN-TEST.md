# Проверка настоящего скана через домашний сервер

Целевой материал: ГАКК, ф. 801, оп. 40, д. 98, JPG 0057. Тест использует настоящий файл в настроенном архиве, а не техническую картинку и не статический ресурс frontend.

## Ограничение доступа

Разрешение владельца задаётся локальным оператором только для выбранного page_id, его оригинала и вырезок, максимум на 30 минут. Дело сохраняет private_only. В State хранится временное разрешение с SHA-256 источника, сроком и случайным идентификатором; действие фиксируется в AuditEvent. GitHub JSON не может самостоятельно создать это разрешение.

HMAC ссылки включает идентификатор разрешения. Срок ссылки не выходит за срок разрешения. Истечение, отзыв ссылки, изменение источника или замена временного разрешения запрещают дальнейшее чтение. Старое разрешение не восстанавливается выдачей нового. Остальные страницы дела остаются закрытыми. Ссылки на реальные документы не включаются в публичную документацию или исходный код.

## Сценарий

Из каталога установленной программы, после явного разрешения владельца на выбранный реальный скан:

```powershell
.venv\Scripts\python.exe -X utf8 scripts\real_scan_probe.py prepare
.venv\Scripts\python.exe -X utf8 scripts\real_scan_probe.py verify
```

prepare сохраняет резервную копию, находит ровно JPG 0057 по фонду/описи/делу, сверяет SHA-256 исходного файла, сохраняет отпечатки существующих записей, создаёт точечное разрешение и отправляет get_pages/get_crop в PRIVATE DREVO-Research-Data. Перед проверкой новой версии сервера требуется обычный перезапуск, чтобы API и worker загрузили её код.

verify ждёт настоящих GitHub-ответов, обращается к выданным ссылкам напрямую через текущий Funnel-origin и через Vercel-proxy. Для полного JPG HTTP-байты сравниваются с SHA-256 файла на домашнем диске. Для вырезки HTTP-байты сравниваются с результатом того же рендеринга оригинала на домашнем ПК. Каждый запрос должен увеличить счётчик Link.hits именно в домашней SQLite. Это отличает динамическую выдачу FastAPI от статического файла или кеша Vercel.

Вырезка задаётся координатами оригинала: x=250, y=200, width=1600, height=1200; результат — 1600×1200 пикселей исходного разрешения. Новые координаты запрашиваются отдельной get_crop-операцией; параметры готовой подписанной ссылки не меняются.

После этого отправляется create_record в inbox/records. Запись явно помечена как интеграционный тест; она не является расшифровкой метрической записи, не задаёт вымышленных персон, дат или родственных фактов. Проверяются GitHub receipt, строка SQLite со статусом proposed, чтение записи через настоящий FastAPI и повтор того же JSON через /api/protocol без дубля. Отпечатки всех ранее существовавших сущностей должны совпасть.

Приватный результат проверки хранится в .local/qa/real-scan-probe.json на текущем ПК. Там находятся действующие до истечения ссылки; не публикуйте этот файл. Смена исходного JPG, удаление диска или остановка сервера делает проверку недействительной. Срок подписей ограничен сервером, а не временем хранения файла в GitHub.

## Результат 7 ноября 2026

Оригинал 2500×1964 получен напрямую через Funnel и через Vercel; в обоих случаях SHA-256 совпал с файлом домашнего диска. Счётчик оригинала в домашней SQLite изменился 0 → 1 → 2. Вырезка 1600×1200 также получена обоими маршрутами, совпала с локальным рендерингом и увеличила свой счётчик 0 → 1 → 2. Запросы без подписи отклонены.

create_record прошёл через настоящий приватный GitHub и домашний worker. Receipt, строка SQLite и чтение через FastAPI подтвердили kind=record и status=proposed. Повтор JSON через /api/protocol вернул прежнюю квитанцию без дубля. Все ранее существовавшие сущности сохранили свои отпечатки; private_only дела не изменился. Автоматизированный набор после добавления точечных разрешений: 45 тестов прошли.
