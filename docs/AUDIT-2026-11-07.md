# ДРЕВО — технический аудит 7 ноября 2026

Проверен существующий проект; архитектура сохранена. Реальный цикл GitHub → подписанный технический JPEG → GitHub → SQLite работает. Пользователь передал правильный случайный код, прочитанный в обычном ChatGPT, до раскрытия эталона в этом чате; код сверен с исходной технической картинкой.

Полная автоматизация обычного чата остаётся ограниченной: стандартное GitHub-подключение ChatGPT поддерживает чтение, а не создание запросов и результатов. Серверный GitHub-токен не добавляет чату инструментов записи. Рабочий вариант без MCP — ручная передача JSON пользователем. Фактический ответ ChatGPT также отправлен этим способом через авторизованный локальный тестовый клиент. Источник ограничения: https://help.openai.com/en/articles/11145903-connecting-github-to-chatgpt.

Указанные Funnel-адреса относятся к проверенному ПК. При переключении ПК start_online.bat публикует действующий origin в AI JSON. Защищённые ссылки используют стабильный Vercel-domain, который проксирует запрос в Funnel. Прямой Funnel-origin также проверен. Секреты, содержимое архива и активные signed URLs в публичную документацию не включены.

## Изменения после аудита

- Добавлены diagnostics и v1 aliases с теми же проверками авторизации.
- Добавлены статические AI index/instructions; общий /ai/* rewrite заменён на точные image/crop маршруты, чтобы JSON/Markdown не уходили в backend вместо статической выдачи.
- Деплой текущего узла копирует public и подставляет реальный Funnel-origin; второй ПК получает корректный AI JSON.
- GitHub-клиент отвергает JSON-скаляры и неподходящий token до создания заголовков; worker проверяет соответствие inbox/request и типа сообщения.
- При временных ошибках GitHub сначала повторно читается файл; потерянное подтверждение уже сохранённого файла не создаёт вторую запись. Branch-head conflict повторяется только при неизменившемся SHA целевого файла. Реальное изменение файла не затирается в таком повторе.
- Устаревшие текущие entity-shards удаляются из генерируемого экспорта, когда сведения исключены фильтром living. GitHub-история прошлых коммитов при этом не стирается.
- Схемы синхронизируются вместе с manifest. Гипотеза добавлена как отдельный kind/операция, без автоматического объединения персон.
- Предложения ChatGPT всегда proposed; uncertain и координаты источника сохраняются. Исправления подтверждённых данных остаются отдельными предложениями.
- Исправлена пагинация поиска по фильтрам: offset применяется к найденным совпадениям, а не к исходным кандидатам.
- Удалены устаревшие инструкции активного использования Cloudflare. Существующий Tailscale не сбрасывался, policy и другой удалённый доступ не менялись.

## Объём доказательств и ограничения

42 автоматизированных backend/API/script теста проходят, включая mock GitHub. TypeScript и Vite production build проходят. Реальный GitHub-тест выполнен отдельным fine-grained token, а не mock и не OAuth-токеном GitHub CLI. Отдельно выполнен реальный браузерный тест Vercel/Funnel на техническом изображении. Публичные AI JSON/Markdown возвращают 200 с application/json и text/markdown соответственно.

Исторические дела, страницы и пользовательские сущности сверены с резервной копией: не изменены. Проверены 9 отдельных файлов/ZIP-элементов по SHA-256; полный архив заново не индексировался. Все 145 реальных дел остаются private_only. Добавлены только явно обозначенные техническое дело, JPEG и предложения теста. JPG не хранятся в SQLite; reference-mode использует существующие файлы, ZIP раскрывается точечно в кеш. Пути и ключ находятся на переносном диске, GitHub-token — в локальном .env ПК.

Кнопки просмотра, импорта, поиска, проверки, резервирования, управления сессиями и ссылками вызывают реальные API. Надпись unverified описывает неподтверждённость полного автоматического клиентского цикла, а не заглушку данных. Поиск работает по сохранённым сведениям, не по непрочитанным сканам: OCR/HTR всего архива не реализован. Fuzzy/расширенные фильтры имеют ограничение 5 000 кандидатов. living — ручная классификация, свободный текст не обезличивается автоматически.

## Windows: после перезагрузки и при смене ПК

Автозапуск Windows отключён. Подключить архив как F:, запустить start_online.bat или ярлык «ДРЕВО — запустить сайт», дождаться сообщения об успешной проверке сайта. Затем открыть /api/v1/health, войти, проверить технический JPG и состояние GitHub в «ChatGPT и GitHub». start_server.bat запускает только локальный API/worker. stop_server.bat останавливает процессы, завершает WAL и сохраняет резервную копию; после этого безопасно извлечь диск. Эквивалентные команды PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start_online.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\stop_all.ps1
```

На втором ПК установить комплект с внешнего диска, подтвердить собственные Tailscale/Vercel-входы и отдельно настроить GitHub token через configure_github.bat. Наличие сохранённого Funnel само не запускает Python после входа в Windows. Перезагрузка или отключение интернета пользователя во время аудита не выполнялись.

Остаётся выбрать ручную передачу JSON для стандартного ChatGPT либо отдельную среду с разрешённой записью в GitHub. Не передавать чату постоянный административный код или серверный token. Перед исследованием настоящего документа владелец проверяет права на конкретное дело и явно разрешает временные ссылки только для него.
