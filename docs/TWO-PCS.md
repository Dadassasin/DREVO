# Работа с внешним архивом на двух ПК

Одна рабочая база находится на внешнем диске рядом с архивом: `F:\Архив\.drevo\drevo.sqlite3`. Папка `.drevo` также содержит ключ подписей, резервные копии и пересоздаваемый кеш. Она исключается из импорта сканов.

На втором ПК подключите диск как **F:** и запустите `F:\Архив\Установить ДРЕВО на этом ПК.bat`. Комплект программы находится в `.drevo\app-source.zip`, отдельно от базы и секретов. Установщик проверяет SHA-256 комплекта, устанавливает Python 3.12, Node.js и Tailscale через winget, размещает ДРЕВО в `%LOCALAPPDATA%\DREVO`, копирует server.env только при отсутствии местной .env, устанавливает зависимости и создаёт два ярлыка на рабочем столе. Если winget отсутствует, нужен Microsoft App Installer из Store; установщик покажет ссылку. Интернет нужен для установки зависимостей и подключения сайта.

Первый запуск попросит подтвердить вход в собственные аккаунты Tailscale и Vercel, а также HTTPS/Funnel. Полностью обойти эти подтверждения скрипт не может. Учётные данные CLI хранятся только на соответствующем ПК; данные службы Tailscale и авторизация Vercel с первого ПК не копируются. При повторном запуске установщика установленный сервер сначала останавливается. Автозапуск сервера в Windows не создаётся.

Для текущего варианта диск должен иметь букву **F:** на обоих ПК. Не публикуйте `.drevo` или server.env в GitHub.

При завершении работы остановите ДРЕВО через `stop_server.bat`, дождитесь сообщения об остановке, затем безопасно извлеките диск. Скрипт завершает запись SQLite WAL и сохраняет копию внешней базы на внутренний диск в `.local\backups\external-last-stop.sqlite3`. Если скрипт сообщает об ошибке, диск пока не отключайте. Подключите его на другом ПК и запустите ДРЕВО. Работайте только с одной базой на диске; старую базу первого компьютера сохраняйте как резервную, не как отдельную рабочую копию.

При запуске сервер проверяет наличие архива и рабочей базы. Отключение диска во время работы опасно для данных; проверка запуска от этого не защищает.

Перед переносом сохраняйте дополнительную резервную копию базы на внутреннем диске, например:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\backup.ps1 -Destination C:\DrevoBackups\drevo.sqlite3
```

Копия в `.drevo\backups` полезна для отката изменений, но не защищает от потери самого внешнего диска. Домашние сканы и база до переноса остаются резервными копиями.

## Переключение сайта

Для обычного запуска используйте ярлык **«ДРЕВО — запустить сайт»** или `start_online.bat`. Скрипт запускает локальный сервер, включает Funnel и автоматически направляет `https://drevo-beta.vercel.app` на этот ПК. При смене ПК публикация маршрутов занимает некоторое время: дождитесь сообщения «Сайт переключён и отвечает». Если сайт уже обслуживает этот ПК и отвечает, повторная публикация пропускается. Проверяется опубликованный маркер маршрута, а не локальная запись, которая могла устареть после работы на другом ПК.

На обоих ПК используйте один Vercel-аккаунт с доступом к проекту `drevo`. Публикуется только интерфейс и конфигурация маршрутов; база, `.env`, ключи, сканы и данные авторизации не загружаются. Ошибка входа или публикации не мешает локальной работе через `http://127.0.0.1:8000`, но онлайн-переключение не считается успешным до проверки сайта. Для исключительно локального запуска остаётся `start_server.bat`.

При переезде: остановить сервер → безопасно извлечь диск → подключить на другом ПК → запустить ярлык сайта. Не запускайте переключение на обоих ПК одновременно. Источники: [Vercel CLI](https://vercel.com/docs/cli/deploy), [Tailscale CLI](https://tailscale.com/docs/reference/tailscale-cli), [winget install](https://github.com/microsoft/winget-cli/blob/master/doc/windows/package-manager/winget/install.md).
