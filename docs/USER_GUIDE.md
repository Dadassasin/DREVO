# ДРЕВО: полное руководство владельца

## Где что хранится

Основной диск данных сейчас — внешний **F:**. В `F:\Архив` находятся оригиналы, а в `F:\Архив\.drevo` — рабочая SQLite, ключ подписей, кеш и установочный комплект. Программа и её зависимости установлены отдельно на каждом ПК: на первом — в папке проекта, на втором установщик использует `%LOCALAPPDATA%\DREVO`.

Диск с данными не является единственной копией всего проекта: исходники хранятся также в GitHub DREVO, обмен исследованиями — в PRIVATE DREVO-Research-Data. Копия сканов на внутреннем диске первого ПК оставлена резервной. Автозапуск сервера Windows отключён.

## Ежедневный запуск

1. Подключить внешний диск. В проводнике должен появиться **F:\Архив**.
2. Нажать ярлык «ДРЕВО — запустить сайт» либо запустить start_online.bat из папки программы.
3. Дождаться сообщения, что сайт уже подключён к этому ПК или успешно переключён.
4. Открыть https://drevo-beta.vercel.app и войти своим кодом.

start_online.bat запускает FastAPI и GitHub-worker, включает сохранённый Funnel и при необходимости обновляет маршрут Vercel на текущий компьютер. Повторная публикация не нужна, если сайт уже обслуживает этот ПК. Нужны работающий интернет и подключённый архив. start_server.bat запускает только локальную часть; локальный адрес — http://127.0.0.1:8000.

## Завершение и перенос на другой ПК

1. Нажать «ДРЕВО — остановить сервер» либо stop_server.bat.
2. Дождаться сообщения об остановке. Скрипт завершает запись SQLite WAL и делает внутреннюю резервную копию.
3. Выполнить «Безопасное извлечение» Windows.
4. Подключить диск к другому ПК, также как **F:**, и запустить сайт его ярлыком.

Работает одна база на внешнем диске. Независимые рабочие копии на двух ПК не создаются. Не отключайте диск во время работы сервера. Для остановки не требуется удалять или редактировать файлы базы.

## Если буква диска другая

Текущие настройки и сохранённые пути страниц рассчитаны на **F:**. С другой буквой запуск откажет в доступе к архиву; данные сохранятся. Назначить букву можно через Win+X → Управление дисками → правой кнопкой по разделу внешнего диска → Изменить букву диска. Диск форматировать не требуется. Если F: занята другим накопителем, сначала разберите назначение букв; замена путей в SQLite вручную не нужна.

## Первый запуск второго ПК

Запустить `F:\Архив\Установить ДРЕВО на этом ПК.bat`. Он проверяет установочный ZIP по SHA-256, устанавливает Python, Node.js и Tailscale через winget, размещает программу в пользовательской папке и создаёт ярлыки. Для загрузки зависимостей нужен интернет. Windows может запросить разрешение администратора.

Войти в собственные Tailscale и Vercel и подтвердить HTTPS/Funnel по показанным ссылкам. Пароли и токены первого ПК не переносятся. Для GitHub-синхронизации на втором ПК отдельно запустить configure_github.bat из установленной программы и сохранить fine-grained token локально. Подробности — TWO-PCS.md.

## Что делать на сайте

- «Архив»: выбрать дело и JPG. Реквизиты из имён каталогов предварительные; номер JPG, страница книги и архивный лист — разные поля.
- Просмотрщик: увеличение, перемещение, поворот, яркость, контраст, вырезка и сравнение фрагментов. Вырезки задаются пикселями оригинала.
- «Добавить транскрипцию»: сохранить чтение рядом с источником. Сомнения, альтернативы и координаты спорного фрагмента сохраняются явно.
- «Люди» и «Исследования»: работа с персонами и задачами; исторические записи и гипотезы выбираются как отдельные типы в форме создания или фильтрах поиска. Совпадение фамилий само не создаёт родство.
- «Проверка AI»: проверить предложение по скану. «Прочтение проверено» отличается от «Подтвердить факт». Для подтверждённой родственной связи нужны подтверждённые доказательства и отдельное подтверждение существенного изменения.
- Поиск работает по сохранённым записям и метаданным. Автоматического распознавания всех непрочитанных сканов нет.

В браузере bearer-сессия хранится только в памяти вкладки: после обновления страницы требуется повторный вход. Роль viewer не может редактировать записи. Код проверяет backend, а не клиентский JavaScript.

## Обычный ChatGPT

Публичный вход — https://drevo-beta.vercel.app/ai/index.json. Инструкции без JavaScript — https://drevo-beta.vercel.app/ai/instructions.md. Чтение технической подписанной картинки обычным ChatGPT реально проверено.

В конкретном пользовательском чате запись JSON в GitHub уже подтверждена фактическими файлами и квитанцией импорта. Проверяйте доступные инструменты своего подключения. Если оно не умеет писать, можно попросить ChatGPT подготовить JSON и вручную добавить файл через GitHub Add file. Worker возвращает responses и receipts и импортирует предложения в SQLite. Постоянный административный код и серверный token в чат не передаются.

Владелец явно разрешил подписанные копии всех 145 существующих исторических дел. Новые импорты по умолчанию private_only. Подписанная ссылка разрешает один ресурс на ограниченный срок: TTL 30 минут и 100 успешных GET; HEAD не расходует лимит. Истёкшая ссылка возвращает 410, продление — новым renew_image_links. Удаление ссылки из GitHub не является отзывом: разрешение отзывается сервером.

get_image_payload через requests/images теперь передаёт байты JPEG Base64-частями через приватный GitHub. Чат собирает .jpg и передаёт файл своему визуальному инструменту, без открытия Vercel/Funnel. delivery=https оставляет старый вариант. Истечение срока удаляет части из текущей ветки, но не Git history. Готовый тест и декодер — [GITHUB-IMAGE-BYTES.md](GITHUB-IMAGE-BYTES.md).

## Проверка состояния

- https://drevo-beta.vercel.app/api/v1/health — безопасный health.
- https://drevo-beta.vercel.app/api/v1/system/capabilities — возможности без секретов.
- «ChatGPT и GitHub» на сайте — состояние worker и квитанции.
- scripts/check_health.ps1 — локальный API, SQLite и подключение Tailscale.

После перезагрузки подключить диск и вручную запустить сайт, затем проверить health, вход и один JPG. После краткого сбоя сети повторить проверку; если сайт не отвечает, снова запустить start_online.bat. Конфигурация Funnel background сохранена в службе; другой удалённый доступ и tailnet policy менять для запуска ДРЕВО не нужно.

## Резервные копии и восстановление

При остановке создаётся `.local\backups\external-last-stop.sqlite3` на внутреннем диске соответствующего ПК. Дополнительная проверенная аварийная копия находится на первом ПК в `.local\backups\recovery-current`: база, ключ и приватные настройки. Она не публикуется и не входит в документацию. Снимок до интеграционного теста также оставлен отдельно. Сканы резервируются отдельно: копия на внутреннем диске первого ПК сохранена.

Ручная копия базы:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\backup.ps1 -Destination C:\DrevoBackups\drevo.sqlite3
```

Восстановление:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\restore.ps1 -Source C:\DrevoBackups\drevo.sqlite3
```

Restore сначала останавливает сервер и сохраняет текущую базу. После восстановления прежние сессии и временные ссылки отзываются. Сами сканы эта команда не восстанавливает. При замене физического диска нужны исходные папки, SQLite, ключ и правильные пути; не начинайте новый импорт вместо восстановления существующей базы.

## Неполадки

| Симптом | Что проверить |
|---|---|
| Архив или база недоступны | Подключён ли диск как F:, существует ли папка .drevo |
| Сайт открывается, данные не загружаются | Работает ли сервер на текущем ПК; запустить ярлык сайта, проверить health |
| 401 | Войти заново; сессия могла закончиться или вкладка обновилась |
| 403 у AI-ссылки | Подпись, разрешение конкретного дела, отзыв и лимит запросов |
| 410 | Срок ссылки закончился; запросить новую через renew_image_links |
| GitHub not_configured | Настроить отдельный локальный token через configure_github.bat и перезапустить сервер |
| GitHub 403/429 | Проверить права/срок токена и лимиты; worker делает паузу при ошибках |
| Vercel просит вход | Подтвердить свой аккаунт с доступом к проекту drevo |
| winget отсутствует | Установить Microsoft App Installer; установщик покажет ссылку |
| Исходный файл изменился | Не подменять его для прежней записи; проверить источник и выполнить контролируемый импорт выбранного материала |

Логи запуска и синхронизации находятся в `.local` папки установленной программы. Не публикуйте .env, signing.key, INITIAL-ACCESS.txt, базу или активные signed URLs в открытом репозитории.

## Для обслуживания программы

Действующий публичный исходный репозиторий — DREVO. PRIVATE DREVO-Research-Data используется для обмена и не является старой неработающей копией. Неудачная GitHub Pages-публикация отключена и удалена из текущей конфигурации. Действующий сайт размещён в Vercel, маршруты переключает CLI; обычный git push сам по себе сайт не обновляет.

На ПК разработки с Git обновить установочный комплект можно командой `python scripts/build_portable_package.py`, а документацию — `python scripts/build_docs.py`. В комплект включаются только отслеживаемые файлы программы, без базы и секретов. На другом ПК после обновления комплекта повторный запуск установщика сначала останавливает установленный сервер, сохраняет местную .env и обновляет программу.

Полный технический аудит, точные API-маршруты, схемы сообщений, архитектура и границы проверки находятся в остальных разделах этой документации. Для печати офлайн HTML используйте Ctrl+P в браузере.


Уточнение после реального обращения из пользовательского чата: файлы requests/pages и inbox/research-progress действительно появились в приватном GitHub. Категоричный вывод о невозможности записи из любого обычного ChatGPT был неверным: возможности зависят от конкретного подключения. Проверяются фактические файлы и квитанции сервера. Поддерживаются inbox/progress и совместимый inbox/research-progress; исследовательская неопределённость не требует вырезки, если это не прочтение документа. Ссылки интерфейса используют /#/archive/..., а не /archive/.... Пакетный get_pages обрабатывается целиком: одна запрещённая страница блокирует пакет.
